# 07 · 路线图与权衡

## 1. 分期路线

每期都有明确的**验收条件**；未达标不进入下一期。

### P0 · 规范与骨架

| 项 | 内容 |
|---|---|
| **目标** | DSL 可被解析、校验、降级；顺序 Flow 可执行 |
| **交付** | Parser · Validator（18 条规则）· Lowering（糖语法 → IR）· Planner（planHash）· Scheduler（顺序）· InlineExecutor · 内存 Journal · Catalog 适配器 · `nexus validate` / `plan` / `run` |
| **不含** | 子 Agent、路由、持久化、审批 |
| **验收** | ① 18 条规则各配正/反例且全部通过；② 纯 `inline` 的顺序 Flow 端到端跑通；③ 诊断含规则号 + 位置 + 修复建议；④ 调度序列 100 次运行完全一致 |
| **风险** | DSL 表达力不足 → 早期用 5 条真实流程反向验证 |

### P1 · 隔离与恢复

| 项 | 内容 |
|---|---|
| **目标** | 多智能体可用；中断可恢复 |
| **交付** | SubagentExecutor · DelegateExecutor · 信封 + schema-repair · `parallel` / `forEach` / `reduce` · join 语义（all/any/quorum）· 持久化 Journal（哈希链）· 恢复算法 · PolicyEngine（权限求交 + 预算） |
| **验收** | ① 扇出 64 实例且并发受控；② 在任意事件后杀进程，恢复后终态与不中断运行一致；③ 预算超限硬停且不自动重试；④ 输出不合规时修复重试恰好 1 次 |
| **风险** | 交接损失导致质量下降 → 用 golden flow 对比 inline 与 subagent 的产出质量 |

### P2 · 路由

| 项 | 内容 |
|---|---|
| **目标** | 按任务描述自动选技能，且质量可度量 |
| **交付** | 候选过滤管线 · `rule` / `embedding` / `llm-select` · 结构化输出校验 · 弃权与升级 · DecisionCache · 路由评估框架 + 回归门禁 |
| **验收** | ① 幻觉技能名 100% 被拒；② 决策缓存命中时不漏记 `RouteDecided`；③ 评估数据集上 Top-1 达预设目标；④ catalog 变更触发评估且回归可阻断合并 |
| **风险** | 技能描述质量参差 → 同步产出《技能元数据撰写规范》（[03 §9](03-routing.md#9-描述即接口)） |

### P3 · 规划与治理

| 项 | 内容 |
|---|---|
| **目标** | 模型可规划子图，但被严格封装；不可逆操作需审批 |
| **交付** | Expander（10 条硬约束）· GateExecutor · 审批面集成 · 审计导出 · 录制/回放（live/record/replay）· Policy hook |
| **验收** | ① 安全用例集（越权动态引用、提权子流程、注入样本）**全部被拦截**；② 重放未命中时失败关闭；③ 审计报告可完整回答 [05 §8.1](05-governance.md#81-journal-即审计日志) 的 7 个问题 |
| **风险** | 封装过紧导致规划不可用 → 用 `onExpandFailure: single-step` 提供渐进降级 |

### P4 · 生产化

| 项 | 内容 |
|---|---|
| **目标** | 可长期运行、可归因、可演进 |
| **交付** | 完整可观测性（span/metrics）· 成本归因（价格表版本化）· ArtifactStore GC · 熔断 · 多租户可行性评估 · 脚本节点可行性评估 |
| **验收** | ① 成本可按 Flow/节点/技能归因；② 工件 GC 不误删被引用对象；③ 长跑（> 1000 Run）无泄漏 |
| **风险** | 成本模型与实际账单不符 → 价格表外置并版本化，定期校准 |

### 1.1 里程碑依赖

```
P0 ──→ P1 ──→ P2 ──→ P3 ──→ P4
规范    隔离    路由    治理    生产
与骨架  与恢复          与规划
  │      │      │      │
  └──────┴──────┴──────┴──→ 每期都产出可独立验证的资产
```

P0 的 Validator 是后续全部阶段的地基：路由（P2）与展开（P3）都复用它，因此 P0 的规则实现质量决定整个系统的安全上限。

### 2.1 与各方案的关系（不是替代）

- **vs LangGraph**：LangGraph 用代码表达图，灵活但不可静态校验、不可声明式治理。Nexus 借鉴其检查点与中断（interrupt）思想，但把图变成**可校验的数据**。
- **vs Temporal**：Temporal 为**确定性业务代码**设计，保证工作流重放。Agent 是非确定性的，需要的是「调度确定 + 内容录制」，而非「确定性重放」。Nexus 借鉴其 Journal/幂等/重试语义。
- **vs Airflow**：Airflow 是批处理调度器，无 Agent 语义（无上下文契约、无信封、无路由）。
- **vs Dify / n8n**：可视化优先，适合低代码；Nexus 规范优先，适合**入库评审**。两者可互补（编辑器生成 Nexus DSL）。
- **vs DSH `workflow` 工具**：见 [06 §7.1](06-reference-impl.md#71-与-dsh-workflow-工具的分工)——它是逃生舱，Nexus 是主路径。
- **vs Anthropic Skills**：Skills 解决了「能力供给」，没有解决「能力组合」。Nexus 正是补上这一层，且**复用** Skills 的发现与加载机制。

> **Nexus 的差异化就一句话**：把编排当作**可编译、可校验、可治理的数据**，而不是脚本或画布。

## 3. 开放问题

每条附**当前倾向**，避免悬而未决。

| # | 问题 | 倾向 | 理由 |
|---|---|---|---|
| Q1 | 静态类型 vs 模型输出自由度 | **schema + 一次修复重试**；允许在明确场景用 `additionalProperties: true` 放宽 | 完全自由 → 下游脆弱；完全严格 → 修复成本高 |
| Q2 | 让模型规划多少 | **默认关闭**；显式 `model-planned` + 10 条硬约束 + 强制审批副作用 | 能力最强也最危险（[03 §6](03-routing.md#6-动态子图展开的封装)） |
| Q3 | 成本模型如何定价 | **价格表外置 + 版本化**，版本记入 Run 元数据 | 否则历史成本无法复算 |
| Q4 | 非确定性下的「确定性」承诺 | **只承诺调度确定性 + 录制回放**，不承诺内容确定 | 承诺做不到的事会腐蚀信任 |
| Q5 | 技能版本钉定语义 | **Flow 内钉精确版本**（`skill@1.2.0`）；catalog 升级需显式改 Flow | 浮动版本让重放与审计失效 |
| Q6 | 多租户隔离 | **v1 不做** | 需要目录/预算/Journal 全面分区，复杂度高（[05 §9](05-governance.md#9-多租户延期)） |
| Q7 | CEL vs 自定义小语言 | **CEL 子集** | 已有实现与生态，语义清晰，可静态分析 |
| Q8 | 作者可控优先级 `policy.priority` | **不做** | 与确定性排序存在张力，且易变成调参地狱（[02 §3.3](02-execution.md#33-确定性排序)） |
| Q9 | 脚本节点（任意代码） | **保持禁用**，直到有独立沙箱与权限模型 | 破坏静态校验与可恢复性（[01 §9.3](01-dsl.md#93-脚本节点v1-保留未启用)） |
| Q10 | 可视化编辑器 | **DSL 优先，编辑器后置** | 编辑器应是 DSL 的视图，而非唯一入口 |
| Q11 | 工件保留与 GC 策略 | 引用计数 + 时间双条件 | 纯时间 GC 会删除被长流程引用的工件 |
| Q12 | 是否需要补偿事务（saga） | **v1 不做** | 副作用回滚应由技能自身负责；编排层只提供幂等键与审计 |

## 6. 成功标准

一个编排系统是否成功，不看它能表达多复杂的图，而看：

| 标准 | 度量 |
|---|---|
| **作者愿意用** | 新增 Flow 中静态引用的比例 > 70%（说明 DSL 够直接） |
| **失败可定位** | 失败 Run 中，能在 5 分钟内定位到具体节点与原因的比例 > 90% |
| **治理有效** | 越权尝试 100% 被拦截；预算超限 0 次未被硬停 |
| **路由可信** | 误路由率低于人工基线的 1/2；弃权率稳定可解释 |
| **可恢复** | 中断恢复后终态与不中断运行一致率 100% |
| **成本可控** | 单 Flow 成本方差可解释（> 80% 的方差能归因到输入规模或重试） |
